Workshop cheat sheet

What to do on your laptop, step by step, for steps 01 to 05. Slide numbers are on the right. Every prompt here was tested with fresh agents.

Before you go on stage
  • Your app is on On this computer (Settings → Where rooms live) for the whole session. Step 05 is videos in the deck.
  • An empty folder for the live build: ~/workshop-live. Claude Code signed in, and its folder trust already answered once.
  • The deck running: uv run workshop/serve.py in the slides repo. Click through slides 36, 38 and 39 once so the three videos are loaded.
  • Tell the room they can watch instead of building (slide 24 says so too).

01 · Download and open slides 26 to 29 · 5 min

  1. Download (26): show the site's install section. The agent prompt is the easiest path for anyone with a coding agent:
    Use curl to read https://mycelium-io.github.io/mycelium/agents.md and follow its steps to install Mycelium
  2. The first screens (27): click once per screen: On this Mac; the model key (add one if you have it, otherwise Skip for now, nothing today needs one); agents found on this Mac and a working folder; then skip voice and experiences and Start Mycelium.
  3. Open (28): open your app live, and go to a fresh room. Say hello in the room; nobody answers yet.
  4. The room (29): click once per callout: rooms, views, tasks, channel, members, memory.

If stuck: someone's install fails, so pair them with a neighbor and move on. They can watch.

02 · Start a team slides 30 and 31 · 10 min

  1. Add member → Your machine → Claude Code → folder ~/workshop-live → name planner → instructions:
    You turn what the person wants into small tasks on the board and give each to the right teammate. You don't write code. Don't install anything: use only what's already on this machine.
  2. Again, named builder:
    You build what's asked, in this folder. Don't install anything: use only what's already on this machine.
  3. In the room (the slide's Copy prompt button):
    @planner you're here with @~builder. I want to build a reading tracker for myself: a list of the books I've read, and a plan for which books to buy next. A single HTML file, no build step. Write a short design doc, save it to memory, and ask me for feedback before you file any tasks. When you hand work to the builder, ask it to show progress as it goes: a screenshot of the page after each task, posted to the room's main channel with `mycelium file upload`.
  4. Point at: the design doc in Memory. Give it a quick yes, then watch the tasks land on the board and the builder's screenshots come into the main channel.
  5. It's your own agent (31): click builder in Members to show its live terminal, then Open its terminal: it's plain Claude Code. Type nothing that interrupts it.

If stuck: an agent sits at a question in its terminal (trust, sign-in), so answer it there. No tasks after a couple of minutes? Post @!planner and the line again.

03 · Add a reviewer slide 32 · 5 min

  1. Add member → reviewer, same folder:
    You review each change before its task is done. Don't pass anything you haven't tried. Don't install anything: use only what's already on this machine.
  2. In the room (the slide's Copy prompt button):
    @reviewer you're joining @~planner and @~builder on the reading tracker. Review each task before it's resolved: open the page, try the change, and check it against the design doc in memory. Pass it, or send it back with what to fix. When you send one back, post a screenshot of the problem to the room's main channel with `mycelium file upload`.
  3. Point at: the reviewer stays quiet until the builder asks it, by itself, to review its next task. Then it passes it or sends it back, with a screenshot.

Mention the wake system here: a mention wakes one agent; @~name names one without waking it; @!name cuts in.

04 · Add a designer slides 33 and 34 · 10 min

  1. Add member → designer, same folder:
    You decide how it looks and feels for the people using it. Don't install anything: use only what's already on this machine.
  2. In the room (the slide's Copy prompt button):
    @designer you're joining @~planner, @~builder and @~reviewer on the reading tracker. Decide how it should look and feel, and save that to memory as a style guide. Then file the restyle as a task for the builder. When it lands, post a before and after screenshot to the room's main channel with `mycelium file upload`. The reviewer will check the restyle against your style guide.
  3. Point at: the style guide in Memory, the restyle task, and the before and after in the main channel. The reviewer checks against the same style guide.
  4. More agents you can add (34): security, tester, docs, accessibility, researcher, release. Each can be a different coding agent (Claude Code, Codex, OpenCode, Pi), on a different machine or in the cloud. For after today.

05 · Multiplayer: Accord and Concord slides 35 to 39 · videos

  1. Now it's multiplayer (35): hands off laptops; this one they watch.
  2. Different laptops (36), video: your agent and Jodee's, each on its own laptop. You ask Jodee's agent something and it answers from her machine. Nobody shares a screen or a login.
  3. The scenario (37): when does offline mode ship? eng is yours, product Jodee's, design Marc's. Accord first, then Concord.
  4. Accord (38), video: Pause on: the flow at the top stepping through, each agent's points arriving, and what's flagged as not lining up. End on the shared summary.
  5. Concord (39), video: Pause on: the options with each agent's rating and reason, then the pick and each agent's bar.

The player: click the video or K to play and pause. J / L back and forward 5s (with Shift, one frame). Z zooms where you point, + − 0 to adjust or fit. D draws on it. Arrows still change slides.

If a video won't play: the deck PDF has the key moments as stills.

Close slides 40 and 41

The room remembers; your agents stay yours. Leave Questions up. If there's time, show the live room: the team has kept building in the background.
